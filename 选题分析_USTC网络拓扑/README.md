## 预实验的 7 个关键信号

1. **加权 Louvain 得到约 25 个社区（Q≈0.69）**，不是原报告标签传播的「82% 巨型社区」。社区划分对算法和边权很敏感。
2. **49.5% 的 URL 是 `/list*.htm` 模板页**；最高边权 `bs ↔ som` 达 4870，权重被少数商学院的模板互链主导。**原始边权不能直接当“重要性”。**
3. **度越低，整站失效率越高**：最低度十分位全挂率 49.5%，高度组接近 0；Spearman ρ≈0.38。但失效站点的度可能被低估（反向因果），只能讲相关。
4. **失效不在网络上聚集**：dead 同配性 −0.063，度保持零模型下仍显著（p<0.001）。这更像“站点个体老化”，不是“共享平台级联故障”。
5. **鲁棒但脆弱**：随机移除 10% 节点 GCC 仍 88%；按度/介数移除 10% 只剩 54–57%；移除 20% 只剩 4–13%。
6. **“关键”与“脆弱”不重合**：高介数节点（teach、staff、news、en）基本全健康；失效集中在低度边缘站点。真正的尾部风险是“核心枢纽将来出问题”，不是“现在已经坏了”。
7. **全挂的是叶子，“半坏不坏”的才在主干上**：162 个全挂站点平均度 1.83，全部删掉网络效率反而从 0.3295 升到 0.3508；149 个部分失效站点平均度 8.58，和健康站点（9.49）接近；全挂+部分失效一起删，GCC 掉到 50.6%（全部剔除认证/robots 后 66.7%）。

> 这 7 条既是选题依据，也可以直接作为报告 Results 的骨架。

## 建议的组内决策方式

1. 四个人各自读 [01](01_数据体检与预实验结论.md) 的「6 个信号」和 [02](02_选题清单与评估.md) 的「评分矩阵」，用 10 分钟独立排序。
2. 开一次 30 分钟会，只讨论分歧最大的两个题。
3. 若没有强烈偏好，直接选推荐题 A；若组里有人偏 ML/统计，选 E；若偏仿真/传播，选 C；若偏运维/可靠性，选 B。
4. 确定后按 [03](03_推荐方案_15天执行计划.md) 的 Day 1 启动，不要再花时间“再想想”。

## 复现环境

- Python 3.13（Anaconda），`networkx 3.4.2`、`pandas 2.2.3`、`numpy 2.1.3`、`scikit-learn 1.6.1`、`matplotlib 3.10.0`
- 所有随机过程固定 seed；图中中文使用 SimHei
- **Louvain 对 Python 的哈希随机化敏感**：复现时设 `PYTHONHASHSEED=0`，否则同一 seed 也可能给出不同社区数（预实验中出现过 23/25 两种结果，Q 都约 0.690）。正式报告建议跑多 seed 并报告分布。
- 运行顺序：`eda.py` → `evidence.py` → `extra.py` → `figures.py`
- 大数据文件不复制，脚本直接读 `../USTC网络拓扑分析/`
