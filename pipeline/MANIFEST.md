# 流水线模块清单（45 个单元 · 9 组）

> 每个单元是一个独立可跑的分析任务。开工前必读 `CONVENTIONS.md` 与 `csa_common.py` 的 docstring。
> 单元编号 = 你的目录名，例：`A1_degree_heavy_tail` → `pipeline/out/A1_degree_heavy_tail/`。
>
> **依赖**：`00_build_data.py` 必须先跑（已完成，31/31 锚点通过）。
> **波次**：W1 = A/B 组；W2 = C/D 组；W3 = E/F/G 组；W4 = H 组（图）+ I 组（审计）。
> H、I 两组**必须**等对应数据单元产出后再跑。

---

## W1 · A 组：拓扑基线与模型对照（5）

| 单元 | 任务 | 必须回答 | 关键坑 |
|---|---|---|---|
| `A1_degree_heavy_tail` | 度/强度分布的重尾刻画：CCDF、Gini、截尾均值；MLE 拟合幂律 / 对数正态 / 指数 / 截断幂律，报 KS 距离与配对似然比 | "是不是无标度"能否被数据支持 | 不许只画双对数直线就说幂律（Clauset et al. 2009）；x_min 要一起报 |
| `A2_small_world` | GCC 上的聚类系数、平均路径、直径、度分布；与同规模 ER / WS / 配置模型的 σ、γ 对照 | 小世界性有多强、哪部分模型解释不了 | ER 的 C 会低几个数量级，σ 要按 Humphries 定义 |
| `A3_null_model_matrix` | 4 个生成模型（ER / WS / BA / 配置模型）× 8 个指标的对照表 + "哪个最像"的定量判决 | 观测网络更像组织型还是增长型 | BA 要固定 seed、≥30 个实例取分布；配置模型有多边/自环 |
| `A4_directed_structure` | 有向图：SCC 规模谱、DAG 缩点、reciprocity、in/out 不对称度、bow-tie 分组（in/tube/out/orphan） | "进得去出不来"有多严重 | 20 条 URL 上限会让出度被系统性截断 → sink 不等于死胡同 |
| `A5_core_periphery` | k-core 剖面、Borgatti–Everett core/periphery 拟合度、rich-club 系数 + 度保持零模型 | 核心—边缘分层是否显著超出度效应 | rich-club 必须对度保持零模型比，否则只是度分布的影子 |

## W1 · B 组：社区结构（6）

| 单元 | 任务 | 必须回答 | 关键坑 |
|---|---|---|---|
| `B1_louvain_stability` | 加权 Gu 上 ≥20 seed 的 Louvain 分布 + 共识矩阵 + 节点顺序敏感性 | "25 个社区"这句话的误差棒 | 已实测 6 个 seed：社区数 23–26、Q 0.6895–0.6945、**最大社区 80–113**；只换建图顺序（边集不变）最大社区 87→84。必须报分布 |
| `B2_algorithm_contrast` | Louvain / 标签传播 / 贪心边介数 / 谱二分 在同一张图上的 NMI·ARI 交叉表 | 社区结论是算法产物还是结构事实 | 标签传播的 557 点巨型社区要复现并解释 |
| `B3_resolution_scan` | γ ∈ [0.5, 2.0] 扫描：社区数 / Q / 与 γ=1 划分的 NMI | 模块度的分辨率限制在这里有多严重 | Fortunato–Barthélemy 2007；小社区会被合并 |
| `B4_weight_variants` | 二值 / 原始权重 / log(1+w) / w≥10 骨架 × Louvain → 社区数·Q·NMI 矩阵 | 权重口径能有多大影响 | 骨架下大量孤立点，`n_comms_nonsingleton` 才是真数 |
| `B5_hub_removal` | 删掉 6 个导航枢纽的全部关联边（505 条 = 全图 20.2%）后社区如何变 | 模板边对社区的真实影响 | 作者"76 社区 Q=0.759"**不复现**：规范实现 seed=42 得 47 个社区（仅 22 个非单点）/ Q=0.7384 / NMI=0.706 vs 全图。枢纽必须用 `csa_common.hub_nodes()` 精确匹配，按短名前缀匹配会误删 30 个 `en.*` 单位站（变 678 条边） |
| `B6_community_semantics` | 社区 × 标题类别列联表、类别纯度、与"按类别划分"的 NMI + 随机基线 | 社区 ≈ 院系吗 | 类别分类器弱（463/671 落"其他"）→ 必须报 κ 或改判据 |

## W2 · C 组：中心性与角色（6）

| 单元 | 任务 | 必须回答 | 关键坑 |
|---|---|---|---|
| `C1_centrality_matrix` | 度/强度/介数/PageRank(有向加权)/PageRank(无向无权)/HITS/k-core/H-index 全表 + Spearman·Kendall 排序相关矩阵 | "重要性"有几个彼此一致的含义 | PageRank 变体必须分列，混用会反转结论 |
| `C2_hub_typology` | 出度 vs 入度双指标：导航型枢纽 / 内容型权威 / 双向枢纽 / 边缘，给名单与占比 | 高度节点是不是同一批 | 死站出度≡0 → 出度类只能用活站子集 |
| `C3_centrality_robustness` | 三种图口径（全图 / 去枢纽 / 强边骨架）下 Top-20 的 Jaccard 重叠率 | 榜单稳不稳 | 不稳就禁止把 Top-10 当结论 |
| `C4_spreaders` | k-core / H-index 对介数与传播重要性的代理能力（Kitsak et al. 2010 复现） | 哪个指标最适合当"影响力"代理 | 需 SIR 或级联的代理指标时要说清是情景模拟 |
| `C5_functional_roles` | Guimerà–Amaral 的 z–P 平面 7 类角色分布 + 各类代表节点 + 与社区划分口径的敏感性 | 网络里有没有"连接者" | z、P 都依赖社区划分 → 必须配 B1 的误差棒 |
| `C6_centrality_vs_health` | 各中心性与 `ok_ratio_pct` / `is_dead` 的相关 + 置换检验（对度保持零模型） | 结构位置能不能预测健康 | 主口径必须用**入度**；总度只作对照 |

## W2 · D 组：失效分布（7）

| 单元 | 任务 | 必须回答 | 关键坑 |
|---|---|---|---|
| `D1_health_gradient` | 度 / 入度 / url_count 十分位 × {全挂率, 部分失效率, 真失效率}，校正前后两套 | 边缘是否更脆弱、有多陡 | 352 个站点正好 20 条 URL，url_count 口径要单列 |
| `D2_censoring_impact` | 系统性量化出度删失：dead 出度 162/162=0、以死站为起点的边=0；给"总度 vs 入度"两套结论对照表 | 哪些既有结论是删失造成的 | 这是本项目最关键的方法学结论，不许含糊 |
| `D3_failure_predictors` | 逻辑回归：`is_true_fail ~ 入度 + log(url_count) + 类别 + 认证站点标记`，报告控制规模后入度是否仍有独立效应 | 网络位置有无独立预测力 | 样本 671、类别不平衡；用交叉验证，不要吹 AUC |
| `D4_assortativity_identifiability` | 证明"死—死相邻"在本数据里**构造性不可识别**；改成可检验的版本：活站是否**回避**指向死站（target-side 置换检验） | 原"失效不聚集 p<0.001"该怎么重写 | 度保持零模型救不了：观测度序列本身已编码出度=0 |
| `D5_failure_clustering_alt` | 换分组维度检验失效聚集：根域前缀 / 类别 / CMS 指纹（扩展名+路径签名）分组间失效率差异 | 有没有"同类一起坏"的信号 | 多重比较要校正（BH） |
| `D6_partial_anatomy` | 149 个部分失效站点：坏的是哪些 URL（路径/扩展名/状态码），失效比例与结构位置的关系 | "半坏不坏"到底是什么病 | 69 个含 -1/-2/403，必须分"干净/含认证"两组 |
| `D7_false_failure_audit` | 逐站核对 32 个 B/C + 1 个 G 的快照记录 | B/C 是否均属于访问受限或跳过 | `passport`/`wp`/`id`/`wvpn` 必须给出证据（状态码分布） |
