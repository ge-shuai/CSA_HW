# D6 · 149 个部分失效站点的解剖 —— 结果

- 口径：主口径 671（run_d6.py:L82） 个有属性节点里的部分失效站 149（run_d6.py:L84）（`ok_ratio_pct`∈(0,100)），锚点 31/31 PASS（`anchors.csv`）。它们的 URL 明细 2507（run_d6.py:L188） 行，其中失败行 827（run_d6.py:L189）（占 32.987635（run_d6.py:L190）%）。
- **强制拆分**：含认证类状态码（-1/-2/403）的 69（run_d6.py:L85） 站 vs 干净的 80（run_d6.py:L86） 站（`csa_common.add_health` 给的 `partial_has_auth_like` / `partial_clean`，两者互斥且并起来正好 149（run_d6.py:L84））。
- 两条口径提醒（§2.1/§2.2）：`ok/bad/ok_ratio_pct` 的分母是**已枚举 URL**（`listed_urls`，上限 20.0），不是全站；`url_count` 是"发现到的条数"，与枚举行数不一致的站有 319（run_d6.py:L177） 个。状态码 -1 / -2 不是失效，403 是服务器应答的访问控制。
- 一致性自检（`key_numbers.csv`）：`ok+bad` 与 URL 行数不符的站 0（run_d6.py:L176） 个；`listed_urls` 与行数不符 0（run_d6.py:L178） 个；打在枚举上限上的站 352（run_d6.py:L180） 个。
- 产物：`d6_partial_sites.csv`（149（run_d6.py:L84） 行逐站）、`d6_code_anatomy.csv`、`d6_code_ext_cooccurrence.csv`、`d6_code_pathsig_cooccurrence.csv`、`d6_site_code_cooccurrence.csv`、`d6_authlike_vs_clean.csv`、`d6_failure_fraction_correlations.csv`、`key_numbers.csv`、`anchors.csv`。

## 0. 判决

1. **部分失效站的"失败"里有一半不是失效。** 827（run_d6.py:L231） 条失败 URL 中，-1（需认证/本轮跳过）+ -2（robots）+ 403（ACL）共占 §2 表的前三行；按 §2.2 只把 -1/-2 视为"非失效"时，剔除后 45（run_d6.py:L218） 个站变成"全枚举都成功"；再连 403 一起剔除，63（run_d6.py:L217） 个站（69（run_d6.py:L85） 个里 62（run_d6.py:L323） 个、80（run_d6.py:L86） 个里 1（run_d6.py:L324） 个）从"部分失效"变成健康。**"149"这个数是口径的产物，不是站点的属性。**
2. **状态码 0 内部还是混的**：全部 URL 里 0 有 421（run_d6.py:L168） 条，标题写明"连接失败-本运行跳过"的 291（run_d6.py:L169） 条、真连接错误（ConnectionError/Timeout/SSLError）130（run_d6.py:L170） 条。同一码位承载了"我没抓"和"它不通"两种意义（D7 逐个看）。
3. **失败 URL 的路径签名高度结构化**（描述，不作断言）：失败行里 1.451028（run_d6.py:L234）% 落在站点根路径，成功行只有 13.869048（run_d6.py:L235）%；失败行平均路径深度 1.949（run_d6.py:L232），成功行 1.861（run_d6.py:L233）。共现表见 §3。
4. **失效率与结构位置：主口径（入度）看不到梯度。** ρ(f, 入度) = -0.0383（run_d6.py:L385）（p=6.427e-01（run_d6.py:L386），bootstrap 5000 轮 95% CI [-0.2050, 0.1315]（run_d6.py:L387））；换成剔除认证类之后的 f_strict 是 ρ=0.1756（run_d6.py:L392）（p=3.215e-02（run_d6.py:L393））。对照口径 ρ(f, url_count) = -0.2787（run_d6.py:L389）（CI [-0.4200, -0.1171]（run_d6.py:L390））——抓取侧暴露量与失效率的关联比结构位置更强，而 url_count 本身受删失，所以这条只能当"共变"读。

## 5. 可辩护的表述

1. "部分失效"=149（run_d6.py:L84） 个站是在"已枚举 URL 里存在非 2xx 行"这一判据下的产物；其中 69（run_d6.py:L85） 个站的失败行里含 -1/-2/403（按 §2.2 不算失效），把这几族剔除后 63（run_d6.py:L217） 个站与"部分失效"的标签不一致。**报告 149 时必须同时报这两个数。**
2. 部分失效站的失败 URL 有明显的**路径形状**：根路径占比 1.451028（run_d6.py:L234）（成功行 13.869048（run_d6.py:L235））、平均深度 1.949（run_d6.py:L232）（成功行 1.861（run_d6.py:L233））。这与"枚举到第几层"的抓取过程共同变化，本文不区分二者。
3. 失效率与网络位置的关联**在主口径（入度）上不存在**（ρ=-0.0383（run_d6.py:L385），CI [-0.2050, 0.1315]（run_d6.py:L387）），与抓取侧暴露量的关联更强但后者受删失污染（§2.1、D2、D5）。可写的句子是"部分失效的深度与站点可枚举性共变，与入度不共变"。
4. 与 D4/D5 接口：D4 说边层面的死—死相邻不可识别；D5 说分组检验里 CMS/类别族有两条伪迹通道；本单元给出同一现象在**站内部**的形态——同一站内哪些 URL 会失败，主要由这条 URL 在第几层、要不要认证决定，而不是由这个站在网络里的位置决定。
